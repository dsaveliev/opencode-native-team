### N-1. Дубликат ключа YAML в `coder.md` — строгий парсер отвергнет файл

`agents/coder.md:18-19`:
```yaml
    "git checkout -- *": "deny"
    "git checkout -- *": "deny"
```

Правило уже было в файле; патч `ffd7efb` добавил его второй раз.
Проверено строгим парсером:

```
agents/coder.md: ❌ DUPLICATE KEY: 'git checkout -- *'
agents/orchestrator.md: OK
agents/planner.md: OK
agents/reviewer.md: OK
agents/tester.md: OK
```

PyYAML по умолчанию дубликаты глотает (последний выигрывает), но строгие
парсеры — в том числе типичные JS/TS-библиотеки, на которых написан opencode —
на дубликате ключа бросают ошибку. Исход при ошибке парсинга frontmatter
в худшем случае: контракт не загружается, агент поднимается с дефолтами,
а дефолты в opencode — `allow`. То есть **самый привилегированный агент
(`edit: allow`, `bash: allow`) теряет все git-деnaи разом.**

Это ровно тот сценарий, против которого строился трек A, и он возник из
опечатки копипасты.

**Фикс:** удалить строку 19. **И это аргумент за C1** — проверка в CI поймала бы
дубликат за секунду; сейчас его не ловит ничто.

### N-2. Фикс из `ecb8051` применён к двум ключам из четырёх

`ecb8051` верно заменил `external_directory: { "*": "deny" }` → `external_directory: deny`
и `webfetch: { "*": "deny" }` → `webfetch: deny`.

Причина, по которой это правильно, относится и к `edit`:

- `webfetch` по документации принимает **только** shorthand — объектная форма
  была невалидна;
- для `external_directory` паттерны — это **глобы путей**, и пример в документации
  использует `**` (`~/projects/personal/**`), а не `*`. Одинарная звезда в глобах
  путей, как правило, не пересекает `/`, поэтому `{"*": "deny"}` мог не совпадать
  с `/Users/…/что-то/вложенное` и не запрещать ничего.

**Но `edit` — тоже глоб путей, и он остался в объектной форме во всех пяти контрактах:**

```yaml
edit: { "*": "deny" }    # planner.md, reviewer.md
edit: { "*": "allow" }   # coder.md, tester.md
```

Если `*` не пересекает `/`, то `edit: { "*": "deny" }` закрывает запись только
в файлы корня репозитория, а `src/foo.go`, `internal/counter.go` остаются
доступны для записи. То есть **read-only роли могут оказаться не read-only** —
при том что это несущая конструкция `design-decisions.md` §3 и строка
«Planner/reviewer can't write files» в новой таблице Security Model в README.

**Фикс:** `edit: deny` / `edit: allow` shorthand во всех пяти файлах, по тому же
основанию, что и `ecb8051`.

`task: { "*": "deny" }` трогать не нужно: там паттерны — имена агентов,
односегментные, `*` работает, и оркестратору объектная форма необходима
для allow-листа.

### N-3. Сравнение хешей — это сравнение префикса, а не равенство

`install.sh`:
```python
if actual[:len(expected_hash)] != expected_hash[:len(expected_hash)]:
```

`expected_hash[:len(expected_hash)]` — это сам `expected_hash`. А `actual`
обрезается до длины ожидаемого. Следствие: если в `MANIFEST.yaml` окажется
усечённый хеш (скажем, `06479d43`), проверка сравнит 8 символов и пройдёт.

В функции, единственное назначение которой — целостность, это сравнение
не должно быть префиксным.

**Фикс:** `if actual != expected_hash:` плюс валидация длины (64 hex-символа)
при парсинге MANIFEST.

Там же, помельче: переменная `name` используется до присваивания, если
`sha256:` встретится раньше первого `- name:` (сейчас порядок в MANIFEST
удачный, но парсер это не гарантирует), и `name` не сбрасывается при записи
без хеша — следующий `sha256:` привяжется к предыдущему имени.

### M-1. Судья жёстко зашит на layout `cmd/` + `internal/`

`judge.sh:39`:
```bash
go test -count=1 -race -coverprofile="$COV_FILE" -coverpkg=./... ./cmd/... ./internal/...
```

`TASK.md` не требует каталога `internal/` — только «Go-модуль; `make build`

не запрещает.

**Фикс:** `./...` вместо перечисления. `-coverpkg=./...` уже стоит, агрегат
не изменится.

### M-2. Метрика `cmd/` считается иначе, чем агрегат, и подаётся рядом как сопоставимая

Агрегат теперь честный (`go tool cover -func` → строка `total:`, взвешено
по операторам) ✅. А `COV_CMD`:

```bash
awk '/\/cmd\//{gsub("%","",$NF); s+=$NF; n++} END{if(n)printf "%.1f", s/n}'
```

— среднее арифметическое **по функциям**. Функция в одну строку со 100 %
компенсирует `main` на 50 строк с 0 %. Та же ошибка, что исправлена в агрегате,
осталась в метрике главного KPI v5 («main > 70 %»), и обе печатаются одной
строкой как однородные:

```
go test -race (weighted coverage 91.5%, cmd 73.2%)
```

**Фикс:** считать по профилю. В `.judge.cov` каждая запись — `файл:диапазон
кол-во_операторов счётчик`; сумма операторов с ненулевым счётчиком по файлам
`cmd/` к общей сумме операторов `cmd/` даёт настоящее взвешенное покрытие.
Либо — минимально честно — переименовать вывод в `cmd (func-mean)`.

### M-3. B2-B4 остались флаки; риск задокументирован вместо устранения

Комментарий в `judge.sh`:
```
# B2: sequence 1..4 (must complete within 2s window — grpcurl startup ~50ms each, ~1.2s total)
```

B2 (4 вызова) + B3 (1) + B4 (1) = шесть процессов `grpcurl`, которые все должны
уложиться в одно окно 2 с. При 50 мс на старт — 300 мс, запас большой.
При 300 мс на нагруженном CI-раннере — 1,8 с, и B4 вместо «сверх лимита»
попадёт в новое окно.

B6 вы от этого риска застраховали (диапазон 5-7) — у B2-B4 корень тот же,
а лечения нет. Решение в комментарии не является решением.

**Фикс:** либо тот же приём (диапазон/ретрай), либо выполнять B2-B4 одним
`grpcurl` с несколькими `-d` (он это умеет), либо заменить на in-process
Go-тест, где окно контролируется.

### M-7. Два из трёх новых deny-правил — пустышки, а дыра из R-6 осталась

Добавлены `*||*`, `*>*`, `*>>*`.

- `*||*` избыточен: `*|*` уже совпадает с любой строкой, содержащей `|`,
  включая `||`.
- `*>>*` избыточен: `*>*` покрывает и `>>`.
- **Перевод строки по-прежнему не ловится** — а именно его называло R-6:
  ```
  cat README.md
  rm -rf ~
  ```
  Совпадает `cat *` (allow), и это последнее совпадение.

То есть расширение блеклиста добавило два no-op правила и не закрыло
указанную дыру. Это не страшно — при наличии предупреждения в README статус
«mitigation» честен, — но стоит либо добавить правило на перевод строки,
либо перестать расширять список и зафиксировать его как есть.

### M-8. Требует проверки до первого прогона: читается ли `.opencode/opencode.json`

`install.sh` кладёт конфиг в `${TARGET}/.opencode/opencode.json`. Все примеры
в документации opencode подписаны просто `opencode.json` без указания каталога.

Ставка высокая: если opencode читает конфиг только из корня проекта,
то молча не применятся **и роутинг моделей, и тест-команды ревьюера** —
то есть обе половины решения об агностичности. Внешне всё будет выглядеть
работающим.

Вместе со смоук-тестом `external_directory` (R-7) это два обязательных
пятиминутных теста перед прогоном.
