## Блокеры

### E-1. Имя файла в репозитории выполняет произвольную команду каждые 5 секунд

`scripts/gen-team-dashboard.py`, `project_loc()`:

```python
out = sh("wc -l " + " ".join(f"'{f}'" for f in files[:500]))
```

`sh()` — это `subprocess.run(cmd, shell=True, cwd=DIR)`. Имена файлов
приходят из `git ls-files` и склеиваются в строку команды через одинарные
кавычки. Апостроф в имени завершает кавычку.

Воспроизведение. Создал в фикстуре файл с именем
`a';touch INJECTED_PROOF;'b.go`, закоммитил, запустил генератор:

```
tracked: a';touch INJECTED_PROOF;'b.go
generator exit=0
--- INJECTED_PROOF present? ---
-rw-r--r--@ 1 ... INJECTED_PROOF
```

Команда выполнилась. Генератор завершился с кодом 0 и ничего не сообщил.
В рабочем режиме это повторяется каждый тик цикла, то есть 720 раз за час.

Безвредный вариант того же дефекта — просто апостроф в имени:

```
=== files tracked: ... it's.go ... ===
<div class=v>0</div><div class=l>loc (tracked)
```

`wc -l` падает целиком, карточка показывает `0`, ошибка проглочена
`except` внутри `sh()`.

Это тот самый D-5, закрытый в `team-dashboard.sh` коммитом `899dd4b`
и воспроизведённый в `gen-team-dashboard.py` в том же релизе. Вектор —
имя файла в репозитории: клонированный чужой проект, ветка из PR,
или файл, который создали сами агенты. Для репозитория, чей README
описывает семь deny-правил на разделители как действующую митигацию
инъекций, собственный инструмент мониторинга не должен собирать команду
конкатенацией.

**Фикс.** Не звать шелл: читать файлы самим — это и быстрее, и считает
корректно (см. E-2):

```python
total = 0
for f in files:
    try:
        with open(os.path.join(DIR, f), "rb") as fh:
            total += sum(1 for _ in fh)
    except OSError:
        continue
return total
```

Если шелл всё же нужен — `subprocess.run(["wc", "-l", *files])` без
`shell=True`. Общее правило по итогам двух раундов: **в этом репозитории
`shell=True` допустим только для константных строк**; любое значение
из git, из конфига или из файловой системы передаётся списком аргументов.
Это стоит записать в SPEC — иначе класс вернётся третий раз.

### E-2. Карточка LOC показывает ровно удвоенное значение

`wc -l` при нескольких файлах печатает строку `total`, а разбор суммирует
каждую строку, начинающуюся с числа:

```python
for line in out.split("\n"):
    m = re.match(r"\s*(\d+)", line)
    if m:
        total += int(m.group(1))
```

Воспроизведение на трёх файлах (3 + 2 + 1 = 6 строк):

```
=== real total lines: 6 ===
       3 one.go
       2 two.go
       1 three.py
       6 total
=== dashboard LOC card ===
<div class=v>12</div><div class=l>loc (tracked)
```

Шесть строк показаны как двенадцать. На реальном проекте карточка `loc
(tracked)` завышена вдвое всегда — кроме проекта ровно из одного файла.

Почему это не поймал тест — см. E-4: в фикстуре ровно один файл кода,
`cmd/main.go`, и `wc` для одного файла строку `total` не печатает.
Проверка `">3<" in page` проходит именно потому, что фикстура вырожденная
в той самой точке, где код неверен.

**Фикс** — тот же, что у E-1: считать строки в Python, без `wc`.

### E-3. Дашборд по умолчанию запускает тесты проекта и блокирует себя на 45 секунд

`test_coverage()`:

```python
ttl = int(cfg_get("coverage_ttl", 60) or 0)
...
r = sp.run(["go", "test", "-count=1", "-cover", "./..."], cwd=DIR, timeout=45)
```

Три проблемы складываются.

1. **Включено по умолчанию.** `coverage_ttl` отсутствует и в
   `examples/team-dashboard.json`, и в README. Любой Go-проект, где
   установлен дашборд, получает полный прогон тестов раз в минуту,
   о котором владелец нигде не прочитает.
2. **Генерация синхронна.** Подставил в `PATH` `go`, который спит 60 с,
   и запустил генератор с **штатным примером конфига**:

   ```
   05:53:40: /private/tmp/covfx/tmp/team-dashboard.html (8840 b, ...)
   took 45s
   go invoked: 1
   ```

   Тик занял 45 секунд вместо долей секунды. Дашборд, который обещает
   обновление раз в 5 секунд, обновляется раз в 50.
3. **При таймауте кэш не пишется.** `pct is None` → `json.dump` не
   вызывается → следующий тик снова запускает `go test`. Для проекта,
   чьи тесты длиннее 45 секунд, это не «раз в минуту», а непрерывный
   цикл: прогон, убийство по таймауту, прогон. Всё время прогона команды.

Последнее важно не только для нагрузки. `-count=1` отключает кэш тестов,
а tester-агент в это же время выполняет свои `go test` с бюджетом
5 минут на задачу. Два параллельных некэшированных прогона конкурируют
за CPU и за build-cache; это ровно тот источник флейков, который репозиторий
методично вычищал в судье (раунды 2-4, `WINDOW_SECONDS`).

**Фикс.** По умолчанию `coverage_ttl: 0` (выключено), в примере конфига
и README — явная строка с предупреждением «запускает тесты проекта».
При таймауте писать в кэш отрицательный результат с собственным TTL,
чтобы не перезапускать немедленно. И запускать не в тике генерации,
а отдельным фоновым процессом, который только кладёт результат в кэш, —
тик обязан быть быстрым, это его единственное требование.

## Существенное

### E-4. Фикстура слепа ровно там, где код неверен

21 проверка зелёная, три живых дефекта. Разбор по каждому:

| Дефект | Почему фикстура не видит |
|---|---|
| E-1 инъекция через имя файла | ни одно имя в фикстуре не содержит кавычки, `;`, пробела |
| E-2 удвоение LOC | ровно **один** файл кода → `wc` не печатает `total` |
| E-3 coverage | `"coverage_ttl": 0` прописан в конфиге фикстуры, Go не ставится в CI |

Третья строка — самая показательная: фикстура отключает функцию, которая
в продакшене включена по умолчанию. То есть тест проверяет конфигурацию,
которой у пользователя не будет.

Это не упрёк к самому тесту — он поймал бы регрессии D-1/D-2/D-4/D-6,
ради которых писался, и это уже окупилось. Упрёк к методу набора данных:
фикстура собрана из «нормальных» значений, а дефекты живут на границах.

**Фикс (конкретный, это главный пункт раунда):**

- второй файл кода в фикстуре + проверка `LOC == сумма строк`, а не
  `">3<" in page`;
- файл с именем `a'b.go` в фикстуре + проверка, что LOC считается
  и посторонний файл не создан;
- `coverage_ttl` не трогать в конфиге фикстуры — проверять **дефолт**:
  подставить в `PATH` заглушку `go`, убедиться, что тик укладывается
  в секунду;
- ассерты на числа вместо ассертов на подстроки: `">12<" in page`
  проходит и для `"112"`. Разбирать значение карточки регуляркой
  и сравнивать с ожидаемым int.

Общий принцип, который стоит зафиксировать: **фикстура обязана содержать
хотя бы одно «неудобное» значение каждого типа, который код принимает
извне** — имя с кавычкой, пустой список, значение за границей, отсутствующий
конфиг.

### E-5. Pause перезагружает страницу ещё один раз после нажатия

```js
if (sessionStorage.getItem('dash-pause') !== '1') {
  setTimeout(() => location.reload(), R);
}
...
function togglePause() { ... sessionStorage.setItem('dash-pause', '1'); ... }
```

Таймер запланирован при загрузке и не отменяется. Нажатие «pause»
только ставит флаг и меняет подпись кнопки — уже запланированная
перезагрузка срабатывает (до `R` секунд спустя), и именно в тот момент,
когда пользователь нажал паузу, чтобы прочитать строку лога. После этой
перезагрузки флаг наконец подействует.

**Фикс:** `const timer = setTimeout(...)`, в `togglePause()` —
`clearTimeout(timer)`.

### E-6. `sessionStorage` без `try/catch` гейтит автообновление целиком

Первое обращение к `sessionStorage` — внутри условия, от которого зависит
`setTimeout(location.reload)`. Если обращение бросает исключение,
скрипт прерывается на первой строке: не будет ни автообновления,
ни восстановления скролла, ни работающей кнопки. Страница при этом
выглядит рабочей — шапка, карточки, «● live».

Это та же сигнатура отказа, которую репозиторий ловил уже дважды:
`e69cea7` («loop died silently, HTML frozen — 'all idle' was staleness,
not inactivity») и `881e022` (пустой график в Safari). Три раза подряд
один и тот же способ сломаться: тихий отказ, который снаружи неотличим
от штатной работы.

Браузером не проверял — это зависит от настроек приватности и от того,
как браузер трактует `file://`-origin. Но механизм отказа определяется
по коду однозначно, и цена страховки — одна функция:

```js
const ss = {
  get(k) { try { return sessionStorage.getItem(k); } catch { return null; } },
  set(k, v) { try { sessionStorage.setItem(k, v); } catch {} },
  del(k) { try { sessionStorage.removeItem(k); } catch {} },
};
```

Отдельно: раз «тихо замерший дашборд» — уже трижды реализовавшийся
риск, его стоит сделать видимым. Генератор знает время своей записи;
пусть страница сравнивает его с `Date.now()` и, если расхождение больше
`3 × refresh`, рисует красную плашку «данные устарели на N с». Тогда
любой будущий отказ этого класса виден мгновенно.

### E-8. `.tx` без `min-width:0` ломает двухколоночный ряд

```css
.tx{white-space:nowrap;overflow:hidden;text-overflow:ellipsis;max-width:52vw}
.row2{display:grid;grid-template-columns:repeat(auto-fit,minmax(320px,1fr))}
```

У флекс-элемента `min-width` по умолчанию `auto`, то есть он не сжимается
меньше содержимого. Многоточие появляется только по достижении `52vw`.

- Панель **Commits** внутри `.row2` занимает около половины ширины окна.
  Строка шириной `52vw` в неё не помещается → `.panel{overflow:auto}`
  даёт горизонтальный скролл в панели.
- Панель **Work log** во всю ширину: текст обрезается на `52vw`, хотя
  доступно около `96vw` — почти половина ширины панели пустая.

**Фикс:** `.tx{min-width:0;max-width:100%}` и `.ev{min-width:0}`;
многоточие тогда считается от фактической ширины панели в обоих случаях.


Проверяется **один** последний текст оркестратора, в порядке от поздних
стадий к ранним. Фраза плана «сначала coder, затем tester, в конце
reviewer» содержит `reviewer` и даёт стадию **review** на первой минуте
прогона. Слово `review` встречается и в `code-review-and-quality` —
названии вендоренного скилла, который оркестратор упоминает в диспетчере.

Степпер — самый заметный элемент страницы, и он врёт тем вероятнее,
чем подробнее оркестратор пишет о своих планах.

**Фикс:** выводить стадию из факта, а не из прозы — по последнему
*завершившемуся* подагенту (`agent` последней сессии с `parent_id`),
с текстом как слабым тай-брейкером. Данные для этого уже загружены.

### E-13. Колонка `spawns` называет не то, что считает

`a["spawns"]` инкрементируется, когда у сессии **есть** `parent_id`,
и приписывается агенту этой сессии. То есть это «сколько раз агента
породили», а заголовок `spawns` рядом с `sessions` читается как «сколько
породил он». Для оркестратора, единственного, кто может порождать,
колонка покажет 0. Переименовать в `spawned`.

### E-14. Мелочи, частью перенесённые из раунда 7

- `DIRTY` по-прежнему вызывает `git status --porcelain` дважды
  (отмечалось в D-11, не исправлено);
- `project_loc()` молча обрезает список на `files[:500]` — на большом
  проекте LOC занижен без всякого признака;
- мёртвый CSS `.pt:hover` — класса `pt` в разметке нет ни одного
  (остался от `1c627b3`, снят в `ea521ff`);
- архивный каталог, чьё имя не начинается с даты, считается **всегда**:
  `if start_date and dm and date < start_date` — при `dm is None`
  фильтр пропускается. Направление ошибки неверное: неизвестную дату
  безопаснее исключать, иначе D-2 возвращается на нестандартных именах;
- в панели Commits время показано как `+Nm` от старта, на графике —
  настенными часами. Две шкалы для одних данных на одном экране;
  привести к настенным.

### E-15. Проверка G-1 уже сузилась до шаблона имени

```python
m = re.match(r"review-v5\.1\.(\d+)\.md", rf)
if m and int(m.group(1)) + 2 not in have_rounds:
```

Файл `review-v5.2.0.md` или `review-v6.md` регуляркой не совпадёт,
`m` будет `None`, и проверка **молча пропустит** его — то есть ровно тот
исход, против которого она написана. Плюс арифметика «K + 2» зашита
в код и сломается на первой же смене схемы версий.

И проверка смотрит только на **присутствие** раздела. Пока она была
зелёной, порядок разделов в журнале успел сломаться: на момент этого
ревью `docs/reviews.md` шёл `1, 2, 3, 4, 6, 7, 5` — раздел раунда 5
оказался в конце файла, после раунда 7. Для документа, чья единственная
функция — хронология, это ровно тот отказ, против которого проверка
писалась; она его не видит, потому что охраняет присутствие, а не
хронологию. Порядок я восстановил вместе с добавлением раздела этого
раунда; проверку на монотонность номеров стоит дописать там же, где
стоит присутствие, — одна строка.

Побочное: проверка требует раздел в журнале в момент появления файла
ревью, то есть **до** того, как появились решения. Поэтому раздел
«Round 8» заведён со статусом «open» — иначе CI красный на самом
акте добавления ревью.

**Фикс:** нумеровать раунд явно — строкой в заголовке самого файла ревью
(`Round: 8`), и проверять соответствие ей, а не выводить номер из имени.

## Наблюдение

Раунд 7 закончился выводом: правило «проверять то, что написано в правиле»
работает, но к новому коду само не переносится, и смоук-тест стоит сделать
«не ради дашборда, а как первый экземпляр жанра».

Тест написан, и он уже работает: ни один из девяти блокеров раунда 7
не вернулся — а четыре из них живут ровно в том коде, который с тех пор
переписывался восемь раз. Это измеримый результат.

Но жанр оказался шире, чем «написать тест». Все три новых блокера прошли
мимо зелёной фикстуры, и причина у них общая: **фикстура собрана
из удобных значений**. Один файл кода там, где ошибка возникает
от второго. Имена без кавычек там, где дефект — в кавычках. Coverage
выключен в конфиге там, где в проде он включён. Тест проверяет не код,
а код на тех данных, на которых автор его и писал.

Это тот же зазор, что раунд 6 нашёл в валидаторе, только сдвинутый
на уровень: тогда проверка была дешёвым приближением правила, теперь
данные — дешёвым приближением реальности. Лечится так же буквально:
в фикстуру кладётся по одному неудобному значению на каждый вход,
который код принимает извне.

Отдельно стоит отметить повторение D-5. Правило было сформулировано
в прошлом раунде конкретно — «путь не интерполируется в тело скрипта» —
и исполнено в том файле, на который указывало ревью. В соседнем файле,
написанном на следующий день, оно нарушено снова. Правило, зафиксированное
только в тексте ревью, живёт до конца того коммита, которым его чинят.
Поэтому фикс E-1 стоит довести до строки в `SPEC.md` и до проверки
в валидаторе (`shell=True` с конкатенацией — grep на десять строк),
а не ограничиваться исправлением функции.
