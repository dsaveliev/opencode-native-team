## Блокеры дашборда

### D-1. `start` больше не начинает новый прогон (регрессия `678fbf3`)

Коммит `678fbf3` делает две вещи: фильтрует сессии по началу прогона и
«preserve state file on restart». Вторая половина отменяет первую.

`scripts/team-dashboard.sh`:

```bash
if [ ! -f "$STATE" ]; then
  python3 -c "... json.dump({'start_ms': ...})"
fi
```

`stop` файл состояния сохраняет намеренно («state + final HTML are kept for
review»). Значит начиная со **второго** прогона в проекте `start` никогда
не пишет новое время — окно прогона навсегда остаётся временем первого запуска.

Воспроизведение (state состарен на 3 часа, затем `start`):

```
run2 state after start: {"start_ms": ...}   # не изменился
run start 01:58:42
<div class=v>3h00m</div><div class=l>elapsed
```

Последствия: `elapsed` и ETA считаются от чужого прогона; `SESSIONS =
load_sessions(START)` снова захватывает сессии прошлых прогонов — то самое
загрязнение токенов/агентов/лога, которое этот коммит и чинил; коммиты
прошлого прогона попадают в таймлайн.

**Фикс.** Разделить «перезапуск внутри прогона» и «новый прогон»:
`stop` переносит state в `team-dashboard-last.json` (финальный вид сохраняется
и остаётся читаемым), `start` всегда пишет новый, `start --resume`
переиспользует существующий. Два изменения по строке каждое.

### D-2. Окно прогона применено к сессиям и коммитам, но не к задачам

`load_tasks()` суммирует чекбоксы по `openspec/changes/*/tasks.md`
**и** по `openspec/changes/archive/*/tasks.md`. Архив — это завершённые
ранее changes, то есть работа прошлых недель, а `ELAPSED` — минуты текущего
прогона.

Воспроизведение: проект с текущим change `2/4` плюс один архивный
change на 40 закрытых задач:

```
<div class=v>42/44</div><div class=l>tasks done
ETA ~0 min (2 left, 0.2 min/task)
<div class=bar><div style="width:95%
```

Головная карточка, прогресс-бар и ETA — все три врут, причём тем сильнее,
чем дольше проект живёт. На реальном проекте с десятком архивных changes
бар будет стоять на 98 % весь прогон.

**Фикс.** Прогресс прогона считать только по активным changes;
архив — отдельной строкой «за проект: N/M» в панели Tasks, не в карточках.
Если нужна именно «аудитория всего проекта» — это вторая пара чисел,
а не та же.

### D-3. `open_browser: true` из примера конфига никогда не открывает браузер

`cfgget` печатает значение через Python `print`, то есть JSON `true`
становится строкой `True`, а сравнение в скрипте — с `true`:

```bash
OPEN_URL="$(cfgget open_browser true)"   # -> "True"
[ "$OPEN_URL" = "true" ] || return 0     # -> не равно, выход
```

Воспроизведено с `examples/team-dashboard.json` как есть:

```
--- cfgget open_browser with example config ---
True
browser WOULD NOT open (value: True)
```

Браузер открывается **только когда файла конфигурации нет** (тогда работает
строковый дефолт `"true"`). То есть сломан ровно тот путь, который
документирован в README и показан в примере: пользователь копирует пример,
и функция выключается.

**Фикс.** `print(str(val).lower())` в `cfgget`, или сравнение
`[ "${OPEN_URL,,}" = "true" ]`. Отдельно — тест на то, что пример конфига
даёт то же поведение, что и его отсутствие.

### D-4. Панель Tasks не может показать ни одной задачи

`load_tasks()`:

```python
elif raw.startswith("#"):
    lines.append(("h", raw.lstrip("# ").strip()))
elif re.match(r"^## ", raw) and cur:
    lines.append(("t", cur[1]))
```

Первая ветка ловит **все** заголовки, включая `## `. Вторая недостижима,
значит элементы вида `("t", ...)` не создаются никогда, а ветка рендера
`elif kind == "t"` — мёртвый код.

Фактический вывод панели на фикстуре с четырьмя задачами:

```html
<div class=tch>demo-change: 2/4</div>
<div class=th>Implementation tasks</div>
<div class=th>1. Wave one</div>
<div class=th>2. Wave two</div>
```

Заголовки и счётчик — без единой задачи. Панель называется «Tasks (2/4)»
и перечисляет только оглавление.

Даже если ветку починить, логика всё равно неверна: `cur` хранит только
последнюю закрытую задачу секции, то есть в лучшем случае показывалась бы
одна задача на секцию.

**Фикс.** Писать строку на каждую задачу прямо в месте разбора, с состоянием:
`lines.append(("x" if done else "o", text))`. Это проще текущего кода
и попутно даёт то, чего в панели сейчас нет совсем, — **список невыполненных**
задач, то есть ответ на вопрос «что команда делает сейчас».

### D-5. Путь проекта подставляется в исходники shell и Python

`scripts/team-dashboard.sh`:

```bash
python3 -c "import json, time; json.dump({...}, open('$STATE', 'w'))"
nohup bash -c "while :; do python3 '$GEN' '$DIR' >/dev/null 2>&1 || true; sleep $REFRESH; done" &
```

`$STATE` и `$DIR` попадают внутрь одинарных кавычек внутри двойных.
Апостроф в имени каталога завершает строку.

Воспроизведение на `/…/O'Brien proj`:

```
SyntaxError: unterminated string literal
dashboard: /…/O'Brien proj/tmp/team-dashboard.html (refresh 5s, pid 9130)
exit=0
```

Состояние не записано, фоновый цикл умер мгновенно (его `bash -c` тоже
не распарсился), но `start` отрапортовал успех с номером PID, а последующий
`stop` сказал «dashboard not running». Пользователь получает замороженную
страницу, которая выглядит живой.

Это не только устойчивость: каталог с именем, содержащим `'; …; '`,
даёт выполнение произвольной команды. Для репозитория, где семь deny-правил
на разделители описаны в README как действующая митигация инъекций,
собственный скрипт не должен собирать код конкатенацией.

**Фикс.** Передавать пути аргументами, а не телом:

```bash
python3 - "$STATE" <<'PY'
import json, sys, time
json.dump({"start_ms": int(time.time() * 1000)}, open(sys.argv[1], "w"))
PY

nohup bash -c 'while :; do python3 "$1" "$2" >/dev/null 2>&1 || true; sleep "$3"; done' _ "$GEN" "$DIR" "$REFRESH" &
```

Плюс проверка `REFRESH` на целое — сейчас строка из конфига уходит прямо
в `sleep`.

### D-6. `refresh` из конфига игнорируется страницей

Цикл перегенерации уважает `refresh`, а HTML — нет: `<meta http-equiv=
"refresh" content="5">` зашит, и подпись в шапке печатает `(5s)` безусловно.

Воспроизведение при `"refresh": 15`:

```
http-equiv="refresh" content="5"
refreshed 04:58:14 (5s)
```

При `refresh: 15` страница перезагружается втрое чаще, чем появляются новые
данные, — три из четырёх перезагрузок выбрасывают скролл пользователя даром.
При `refresh: 2` — наоборот, данные свежее, чем показано.

**Фикс.** Передавать интервал генератору (аргумент или `TEAM_DASHBOARD_REFRESH`)
и подставлять в оба места.

### D-7. HTML пишется неатомарно

```python
open(OUT, "w", encoding="utf-8").write(page)
```

Файл усекается, затем заполняется ~20 КБ. Браузер перечитывает его по таймеру
каждые 5 секунд без всякой синхронизации — попадание в окно даёт пустую
или оборванную страницу. Вероятность невелика, но за часовой прогон
перезагрузок 720.

**Фикс.** `os.replace(OUT + ".tmp", OUT)` — переименование в пределах
каталога атомарно.

## Умеренное (дашборд)

### D-8. Валидатор не проверяет дашборд, а только его синтаксис

Шаг `[7]` — `ast.parse(...)` и `bash -n`. Ни один из D-1…D-7 так не ловится:
все они — поведение, а не синтаксис. Дашборд при этом уже отгружается
`install.sh` в каждый проект.

**Фикс (и он же самый ценный пункт раунда).** Смоук-тест на фикстуре,
~30 строк: создать временный каталог, `git init`, два коммита, `tasks.md`
на 4 задачи, запустить генератор и проверить ассерты —
`tasks done` равно `2/4`; в панели Tasks присутствует текст задачи;
`meta refresh` равен настроенному; файл — валидный HTML без незакрытых тегов.
Плюс отдельный ассерт `cfgget open_browser` → `true`. Это закрывает D-2,
D-3, D-4, D-6 механически и навсегда.

### D-9. PID-файл не идентифицирует процесс

`running()` — `kill -0 "$(cat PIDFILE)"`. После перезагрузки или долгой
паузы PID переиспользуется ОС, и `stop` пошлёт `kill` чужому процессу.

**Фикс.** Сверять командную строку: `ps -p "$pid" -o command= | grep -q
gen-team-dashboard` перед тем, как считать его своим и перед `kill`.

### D-10. В целевом проекте `tmp/` не игнорируется

Дашборд пишет `tmp/team-dashboard.html`, `.pid` и `.json`; контракты
(`agents/coder.md`, `agents/tester.md`, `agents/orchestrator.md`) требуют
класть временные файлы в `./tmp/`. `.gitignore` **этого** репозитория
содержит `tmp/`, но `install.sh` ничего не добавляет в целевой проект.
Результат — оркестратор коммитит HTML, который переписывается каждые
5 секунд, а карточка `dirty files` считает собственные артефакты дашборда.

**Фикс.** `team-dashboard.sh` при `start` пишет `tmp/.gitignore` с
содержимым `*` — самоигнорирующийся каталог, чужой `.gitignore` не трогаем.

### D-11. Лишняя работа каждые 5 секунд

- `git status --porcelain` вызывается дважды подряд ради одного числа;
- `git log --reverse` читает всю историю, хотя при наличии state нужен
  `--since`;
- `load_parts` выбирает **все** части всех сессий и парсит JSON у каждой,
  без `LIMIT` и без фильтра по типу;
- поиск агента внутри цикла — `next((s["agent"] for s in SESSIONS ...))`,
  то есть O(частей × сессий) вместо словаря `sid → agent`.

На часовом прогоне таблица `part` — десятки тысяч строк; это главный
источник нагрузки, и он повторяется 720 раз.

### D-12. Мелочи качества

- `open()` без `with` в шести местах (`run start`, `load_tasks`, запись
  вывода) — дескрипторы живут до сборки мусора;
- `fmt_k`: `1500 → "2k"`, `1900 → "2k"` — токены двух агентов сливаются
  в одно число; до 10k нужна одна десятичная;
- `except Exception: return []` при недоступной БД — пользователь видит
  дашборд из нулей без единого намёка на причину; нужна строка диагностики
  в `meta` («opencode DB not found at …»);
- порог «активности» 90 000 мс повторён тремя литералами.

## Дизайн, UI, UX

Разделяю на «мешает прямо сейчас» и «добавляет ценность».

### Мешает

1. **Полная перезагрузка страницы каждые 5 секунд** — главный дефект
   интерфейса. Выбрасывает позицию скролла в обеих лентах, снимает
   выделение текста (нельзя скопировать строку лога — она исчезнет
   на следующей перезагрузке), сбрасывает фокус. Лента на 40 записей
   со `max-height:300px` практически нечитаема.
   **Фикс без зависимостей:** сохранять `scrollTop` каждой `.feed`
   и окна в `sessionStorage` перед `beforeunload`, восстанавливать
   на `load`. Десять строк инлайн-скрипта, и страница перестаёт «прыгать».
2. **Кнопка «refresh» бессмысленна** при автообновлении раз в 5 секунд.
   Полезна обратная: **pause** — остановить метаобновление (убрать тег
   из DOM), чтобы прочитать и скопировать лог; повторное нажатие
   возвращает. Это единственное действие, которого пользователю реально
   не хватает.
3. **Фиксированная ширина SVG 860 px** и `grid-template-columns:1fr 1fr`
   без media-query. На узком окне (половина экрана рядом с терминалом —
   типичный сценарий для живого дашборда) таймлайн уезжает в горизонтальный
   скролл, а колонки сжимаются до нечитаемости.
   **Фикс:** `width="100%"` при сохранённом `viewBox`, и
   `grid-template-columns:repeat(auto-fit,minmax(360px,1fr))`.
4. **Нет тёмной темы.** Прогон идёт рядом с терминалом; белое полотно
   `#f4f5f7` на 40 минут — это физически неприятно.
   **Фикс:** палитра токенами в `:root`, переопределение в
   `@media (prefers-color-scheme: dark)`. Цвета ролей уже вынесены
   в `AGENT_COLORS` — им нужна вторая, более светлая версия для тёмного фона
   (`#b91c1c` на тёмном нечитаем).
5. **Цвет — единственный носитель роли** в ленте и в таблице агентов.
   Для дейтеранопии `coder` (#3f8f5f) и `tester` (#b45309) различимы плохо,
   а `reviewer` (#b91c1c) и `tester` сливаются.
   **Фикс:** короткий бейдж перед именем (`ORC`/`COD`/`TST`/`REV`) или
   фоновая плашка с разной насыщенностью; цвет остаётся вторичным кодом.
6. **Прогресс-бар без подписи.** Полоса на 10 px без числа и без
   объяснения, что в неё входит (с учётом D-2 — ещё и не то, что думает
   читатель). Нужны процент справа и подпись «tasks in active changes».

### Добавляет ценность

7. **Что именно делает команда — на дашборде нет.** Ни текста
   ассигнмента, ни имени change, ни текущей стадии. Владелец смотрит
   на дашборд ради одного вопроса: «где мы сейчас?» — а стадия
   (plan → code → test → review → commit) не показана нигде, хотя она
   выводится из того, какой агент активен последним.
   **Фикс:** строка-степпер под шапкой, с подсветкой текущей стадии
   и временем в ней. Это самый заметный прирост пользы на единицу кода.
8. **Невыполненные задачи важнее выполненных.** Сейчас панель
   (после починки D-4) показывала бы только закрытые. Полезнее порядок:
   текущая задача крупно, следующие три — ниже, закрытые — свёрнуты
   в счётчик.
9. **Карточка `tool errors` — число без содержания.** Ошибки уже
   собираются с именем инструмента (`errors.append((t, tool))`), но
   отбрасываются. Показать последние три: `bash ×2, edit ×1` с временем —
   данные уже есть, рендера нет.
10. **Карточка «elapsed · ETA ~18 min (4 left, 4.5 min/task)»**
    перегружена: метрика и длинная подпись в блоке шириной 110 px.
    ETA заслуживает отдельной карточки, а подпись про `min/task` —
    тултипа.
11. **Таймлайн коммитов.** Путь стартует с `y(1)` и сразу прыгает на `y(2)`
    при том же `x` — в начале графика вертикальный штрих, выглядящий как
    артефакт. Нет отметки «сейчас» (вертикальная линия на `ELAPSED`),
    из-за чего непонятно, насколько давно был последний коммит.
    Ось Y без заголовка («commits, cumulative»).
12. **Нет favicon и нет имени проекта в начале `<title>`.** При нескольких
    открытых дашбордах вкладки неразличимы. `<title>` стоит начать
    с состояния: `● 2/4 · project — team dashboard`, тогда прогресс виден
    в самой вкладке, не разворачивая окно.
13. **Семантика разметки.** Таблица без `<thead>`/`<th scope>`;
    `.muted` 11 px серым `#66707c` — на границе читаемости;
    `.ev .ag{min-width:86px}` ломается на длинных именах агентов.
14. **Пустые состояния неинформативны.** «waiting for output…» одинаково
    означает «команда думает» и «БД не найдена» (D-12). Разные тексты —
    разная реакция пользователя.

## Общее (вне дашборда)

### G-1. Журнал ревью снова отстаёт — и проверка, обещанная в раунде 6, не добавлена

`docs/reviews.md`: шапка «**Six** external review rounds shaped v5 → v5.1.4»,
разделы — с `Round 1` по `Round 5`. Раунд 6 (ревью v5.1.4, находки C-1…C-6)
в журнале отсутствует, хотя `docs/review-v5.1.4.md` лежит в репозитории

## Наблюдение

Раунд 6 закончился выводом: «инвариант формулируется в прозе точно,
а в коде — его дешёвым приближением». Этот раунд даёт прямую проверку
этого вывода на двух независимых примерах.

Там, где приближение заменили на настоящее сравнение (C-1 → `JSON ⊇
frontmatter`), класс исчез: я пытался пробить шаг `[5]` урезанной картой
и не смог. Там, где проверку обещали, но не написали (C-4 → раздел
в журнале), дефект вернулся в первом же релизе — и вернулся ровно
в прежней форме.

Дашборд — третий пример, самый показательный, потому что он писался
**после** формулировки урока. Новый компонент получил проверку
`ast.parse`, то есть опять самое дешёвое приближение к правилу «дашборд
показывает верные числа». Семь дефектов, из них четыре — неверные числа
на главных карточках, и все четыре ловятся одним тестом на фикстуре
из тридцати строк.

Вывод практический: правило «проверять то, что написано в правиле»
работает, но применяется только к тому, что ревью назвало явно.
К новому коду оно не переносится само. Пока в репозитории нет ни одного
теста поведения — только статические проверки — каждый новый компонент
будет начинать с нуля. Смоук-тест дашборда стоит сделать не ради дашборда,
а как первый экземпляр этого жанра.

Отдельно: находка D-1 — регрессия, внесённая исправлением предыдущей
находки того же коммита. Это аргумент в пользу того же пункта: правка,
которую нечем проверить, с ненулевой вероятностью отменяет сама себя.
