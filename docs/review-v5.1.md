## Блокеры

N-1. Дубликат ключа YAML в coder.md:18-19. Патч добавил
"git checkout -- *": "deny" второй раз. Проверил строгим парсером:

agents/coder.md: ❌ DUPLICATE KEY: 'git checkout -- *'
остальные четыре: OK

PyYAML дубликаты глотает, строгие JS/TS-парсеры — бросают. Если opencode
отвергнет frontmatter, агент поднимется с дефолтами, а дефолт — allow. Самый
привилегированный агент (edit: allow, bash: allow) теряет все git-деnaи разом —
ровно тот сценарий, против которого строился трек A, из опечатки копипасты.

N-2. ecb8051 применён к двум ключам из четырёх. Фикс верный, и основание у него
двойное: webfetch по докам принимает только shorthand, а для
external_directory паттерны — глобы путей, где одинарная * не пересекает /
(в примере доков стоит **). Но edit — тоже глоб путей, и он остался объектом
во всех пяти контрактах. Если * не пересекает /, то edit: { "*": "deny" }
закрывает запись только в корень репозитория, а src/foo.go остаётся доступен.
То есть read-only роли могут не быть read-only — при том что это несущая
конструкция §3 и строка в новой таблице Security Model. task трогать не нужно:
там паттерны односегментные.

N-3. Сравнение хешей — префиксное.
actual[:len(expected_hash)] != expected_hash[:len(expected_hash)] — правая часть
равна самой себе, левая обрезается. Усечённый хеш в MANIFEST пройдёт проверку
по первым N символам. В функции, назначение которой — целостность.
